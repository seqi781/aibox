AI CODING TERMINAL · DOCKER

给 AI 一台终端，
边界由你来定。

aibox 在 Docker 里运行 Claude Code、Codex 等 AI 编程工具。所有流量强制走你指定的代理节点或 VPN，断线就断网；只有你授权的目录对 AI 可见。宿主机的网络设置一点不动。

  • Windows 可在 WSL2 中使用

WHY AIBOX

把 agent 放进容器，
六个顾虑各有答案。

在自己电脑上让 AI 写代码、跑命令，担心的往往是同几件事。aibox 把每一件都落到了具体的机制上。

01 / FILES

agent 会不会顺手读到 ~/.ssh，或者别的项目？

只有授权的目录对它可见

在配置里逐个列出目录，每个单独设为只读（ro）或读写（rw），挂到 /workspace 下。ro 由内核强制，容器里的 root 也写不进去。默认拒绝挂载整个主目录、根目录、~/.ssh 等凭据目录、Docker socket，以及 aibox 自己的目录（防止 AI 借此改动网关配置）。

02 / COMMANDS

它在终端里跑的命令，会不会改到我的电脑？

命令都在容器里执行

Claude Code、Codex 运行在 workspace 容器中，看不到宿主机的进程和其它文件。容器去掉了 NET_ADMIN、NET_RAW、SYS_ADMIN，不挂载 Docker socket，也不开 privileged。

03 / EGRESS

分流规则会不会让一部分流量直连？DNS 和 IPv6 呢？

只有一个出口，其余默认拒绝

网关防火墙默认拒绝，应用流量只有一条规则：全部走代理。节点筛选没匹配到、订阅下载失败时，网关直接断网，不会回落直连。DNS 在网关本地解析并经隧道转发，程序硬编码 8.8.8.8 也会被拦下；IPv6 直接禁用。

04 / KILL SWITCH

代理掉线以后，流量会不会回落到直连？

断线就断网，恢复后自动重连

代理进程崩溃或 VPN 断开时，没有隧道就没有出路，流量被阻断，不会回落到直连。mihomo 会被自动拉起，gluetun 自己重连 VPN，工作容器不用重启。

05 / HOST NETWORK

我不想为此改动整台电脑的网络设置。

宿主机网络保持原样

所有防火墙规则只作用于容器自己的网络命名空间。浏览器、系统代理和其它程序照常走原来的网络，互不干扰。

06 / WEIGHT

为了隔离，是不是得开一台完整的虚拟机？

两个容器，一台完整的终端

不用额外装虚拟机。直接用你自己的系统终端进入，里面有 bash、git、node、python 和编译工具链，不是只能跑几条命令的玩具沙箱；需要时加 --tmux，关掉终端任务照样在跑。

HOW IT WORKS

流量只有一条路，
其余全部拒绝。

网关容器独占网络栈，workspace 容器没有自己的网卡，和网关共享同一个网络命名空间，只能从网关出去。网络管理权限都在网关里，AI 所在的容器一项也没有。

  • 直连物理网卡：在网关里绕过隧道直接从 eth0 出去，会被防火墙拒绝。
  • 宿主机或局域网代理：网关连接上游的流量只能去公网地址，连不到本机的 Clash。
  • Docker 内置 DNS：127.0.0.11 可能经宿主机转发，直接封掉，DNS 只走网关本地。
  • IPv6：sysctl 关闭，ip6tables 全部拒绝；两者都没生效时网关拒绝启动。
  • mihomo 网关（Clash Meta 内核）：使用订阅或 Clash 节点，TUN 在三层接管全部流量，不认代理环境变量的程序也逃不出去。
  • gluetun 网关：自建 WireGuard，或 gluetun 支持的商业 VPN（WireGuard / OpenVPN），自带 kill switch。
  • 先上防火墙，再启动代理：启动阶段就是默认拒绝。代理的控制接口只在网关内部，agent 切不到直连模式。
  • 边界：拉取镜像和 docker build 走宿主机网络，不在运行时隔离的范围内；AI 工具本身在运行时经隧道安装。

STRICT EGRESS

本机的 Clash，
不能当上游。

本地代理软件有自己的分流规则，一部分流量可能按规则直连。如果把它当作上游，出口就不再由 aibox 控制。所以上游必须是远程节点或订阅，你在 Clash 里用的订阅链接，直接填进来就行。

  • 第一层，配置校验：节点地址不能是 localhost、*.internal、*.local，也不能是私有或保留网段；不允许 type: direct。
  • 第二层，防火墙兜底：订阅里的域名即使解析到宿主机或内网，网关也连不上。
  • 失败不留痕：校验不通过时返回非 0，原来的配置保持不变。
  • 代价：部署在局域网或 Tailscale（100.64/10）里的节点也会被拒绝，目前没有例外开关。

COMPARISON

和本地代理软件，
管的不是同一件事。

本地代理软件面向整台电脑的日常上网，分流规则正是它的长处。aibox 只管一件事：给 AI agent 一个出口固定、文件受限的工作环境。两者可以同时使用，aibox 不会动你电脑上的代理设置。

给 AI 编程工具配网络的两种方式
方面在宿主机上直接使用本地代理软件aibox
出口是否可控 由分流规则决定，部分流量可能按规则直连；系统代理模式下，不认代理设置的程序会直接走本地网络。 只有一条“全部走代理”的规则，TUN 或 VPN 在三层接管容器内的全部流量。
断线是否阻断 取决于软件和所选模式，各家做法不同。 默认拒绝：隧道断开即断网，恢复后自动重连；可以用 doctor --full 实际验证。
文件可见范围 和网络无关，agent 以当前用户身份运行，能读到该用户能读的文件。 只有授权的目录，每个目录可单独设为只读。
对宿主机网络的影响 系统代理或 TUN 模式作用于整台电脑。 不影响，规则只在容器的网络命名空间里生效。
更适合 整台电脑的日常网络使用。 让 AI agent 在隔离的环境里长时间工作。

GET STARTED

三步上手，
剩下的交给向导。

需要准备：Docker，以及一个代理订阅、Clash 节点或 WireGuard 配置。首次启动要构建镜像，大约 3～5 分钟。

  1. [1]

    安装 Docker

    macOS 用 OrbStack 或 Docker Desktop，装好后启动它；Linux 用 Docker Engine，装完重新登录一次。

    macOS 
    brew install orbstack
    Linux 
    curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER

    Windows：安装 Docker Desktop 并开启 WSL2 集成，之后的步骤都在 WSL 终端里进行。

  2. [2]

    获取 aibox，运行配置向导

    向导只问两件事：出口（粘贴订阅或分享链接，自动识别并当场测试）和授权目录，回车即采用默认值。最后可以安装 aibox / ai 命令和 Tab 补全，直接启动并体检。

    bash
    git clone https://github.com/OWNER/aibox ~/aibox
cd ~/aibox
./aibox init
  3. [3]

    在项目里启动 Claude Code

    首次运行时按提示登录一次，凭据保存在持久化的 home 卷里。它直接运行在你当前的终端里；想关掉终端后继续跑，加 --tmux。

    ai c myapp
  • [1/3]环境检查：Docker、Compose 版本，Linux 上还检查 TUN 设备。
  • [2/3]网络出口：粘贴订阅或分享链接，自动识别格式，当场测试并汇报可用节点、延迟、出口 IP 和地区。
  • [3/3]授权目录：路径支持 Tab 补全，每个目录选 rw 或 ro。
  • 自动时区和语言跟随出口 IP 的地区；AI 工具第一次使用时自动安装。
  • ai c myapp在 /workspace/myapp 启动 Claude Code
  • ai x myapp在项目里启动 Codex
  • ai进入容器终端（按当前目录定位到项目）
  • ai c --tmux关掉终端也继续运行
  • ai st状态和出口 IP
  • ai q停止（数据保留）

FOR AI AGENTS

让宿主机上的 agent，
替你把它配好。

每一项配置都有对应的非交互命令。仓库里的 AGENTS.md 和 CLAUDE.md 会被 Codex 和 Claude Code 自动读取，里面写了配置流程、报错的处理方法和不能越过的安全边界。在仓库目录里对 agent 说一句“帮我把 aibox 配好”就可以开始。

非交互配置 · 订阅链接和目录换成你自己的
./aibox init --defaults                     # 生成默认配置，不覆盖已有配置
./aibox import "https://example.com/your-sub" --filter '日本|JP'   # 自动识别并测试
./aibox mounts add rw ~/code/myapp
./aibox mounts add ro ~/Documents/specs
# 可选：用 API Key 而不是账号登录时
printf %s "$ANTHROPIC_API_KEY" | ./aibox config key ANTHROPIC_API_KEY
./aibox config check && ./aibox up && ./aibox doctor --full
  • 不提问，看返回码：成功返回 0，失败返回非 0，原因写到 stderr。
  • 失败不改动原配置：比如节点不合规，写入会被撤回，可以放心重试。
  • 密钥不进命令行：API Key 只从标准输入传入，VPN 密钥从环境变量读取，不会出现在命令参数里。
  • 不猜、不越界：订阅链接和要授权的目录由 agent 向你询问；它不会去改防火墙规则、放宽挂载范围或挂载 Docker socket。

DOCTOR

隔离有没有生效，
跑一遍就知道。

aibox doctor --full 不只读配置，而是在容器里实际发请求验证：出口、DNS、IPv6、权限、挂载，还会模拟一次断线，确认流量被阻断后再恢复。全部打勾才算通过，有失败项时返回非 0。

  • 出口容器的出口 IP 和地区，并和宿主机出口对比；两者相同会给出警告。
  • DNS是否走网关本地解析；硬编码 8.8.8.8 是否也被劫持；权威 DNS 看到的来源是否是出口网段。
  • IPv6IPv6 是否无法出网，容器里有没有全局 IPv6 地址。
  • 隔离workspace 的能力集；绕过隧道直连是否被拒；上游是否只能是公网；控制接口是否不可见。
  • 断线停掉代理或拉下 VPN 网卡，确认请求被阻断，再确认自动恢复。
  • 挂载每个授权目录的实际读写权限和配置的 ro / rw 是否一致。
aibox doctor --full

NOTE上面的检查项以 mihomo 网关为例；使用 gluetun 时，DNS 和隔离部分的项目会少一些，断线测试改为拉下 VPN 网卡。

FAQ

动手之前，
你可能想问。

能不能直接用电脑上正在运行的 Clash？

不能，这是有意的设计。Clash 的分流规则可能让一部分流量直连，出口就不受控了。指向本机、宿主机或局域网的上游会在配置校验和防火墙两层被拒绝。

做法是把 Clash 里用的订阅链接填进来：aibox config proxy --sub "订阅链接"。

支持哪些系统？

支持 macOS（Apple Silicon 和 Intel，推荐 OrbStack，Docker Desktop、Colima 也可以）和 Linux（Docker Engine 25 及以上、Compose 2.24 及以上）。

已实测的环境是 Ubuntu 24.04 arm64、Docker 29、Compose 2.40，两种网关都通过了 doctor --full；脚本兼容 macOS 自带的 bash 3.2。真实的 Mac、SELinux 系统（Fedora / RHEL）和 rootless Docker 还没有实测过，遇到问题欢迎反馈。

首次启动要多久？

大约 3～5 分钟，主要是构建两个镜像。AI 工具在第一次运行 ai c / ai x 时经隧道安装。之后再启动不需要重新构建，AI 工具、登录凭据和 shell 历史都保存在持久化的 home 卷里。

Windows 怎么用？

在 WSL2 里使用：安装 Docker Desktop 并开启 WSL2 集成，然后在 WSL 终端里 git clone 并运行 ./aibox init，之后的用法和 Linux 一样。

--yolo 跳过确认，安全吗？

ai c myapp --yolo 会跳过工具自身的逐条确认。容器本身就是沙箱：agent 只能改动你授权为 rw 的目录，网络只能走网关。但在 rw 目录里，它可以做任何修改，所以重要的资料建议用 ro 授权，项目本身最好在 git 管理之下。

代理节点断了会怎样？

容器里的程序会直接连不上网，而不是改走本地网络。节点恢复后自动重连，不用重启容器。如果 aibox up 提示网关不健康，运行 aibox logs gateway 查看原因，常见的是订阅下载失败或节点全部不可用。

aibox 和 Anthropic、OpenAI 有关系吗？

没有。aibox 是独立的开源项目，只是在容器里运行这些工具，与 Anthropic、OpenAI 没有任何关联，也未获得它们的认可。使用 Claude Code、Codex 需要遵守各自的服务条款。
