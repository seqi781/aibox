AI CODING TERMINAL · DOCKER

Give the AI a terminal,
you set the walls.

aibox runs Claude Code, Codex and other AI coding tools inside Docker. Every packet goes through the proxy node or VPN you choose, and if the tunnel drops, so does the network. Only the folders you grant are visible. Your host's network settings stay untouched.

  • macOS · Linux

WHY AIBOX

Six common worries,
six concrete answers.

Letting an AI write code and run commands on your own machine tends to raise the same handful of concerns. aibox answers each one with a concrete mechanism.

01 / FILES

Will the agent wander into ~/.ssh or my other projects?

It only sees folders you grant

List folders one by one, each read-only (ro) or read-write (rw), mounted under /workspace. ro is enforced by the kernel, so even root inside the container can't write. Mounting your whole home directory, /, credential folders such as ~/.ssh, the Docker socket, or aibox's own folder (so the AI can't rewrite the gateway config) is refused by default.

02 / COMMANDS

Could the commands it runs change things on my machine?

Commands run in a container

Claude Code and Codex run in the workspace container and can't see host processes or other files. It drops NET_ADMIN, NET_RAW and SYS_ADMIN, doesn't mount the Docker socket, and isn't privileged.

03 / EGRESS

Will split-routing rules send some traffic direct? What about DNS and IPv6?

One way out, everything else denied

The gateway firewall defaults to deny, and app traffic has exactly one rule: everything through the proxy. If the node filter matches nothing or the subscription fails to download, the gateway goes offline instead of falling back to a direct connection. DNS resolves at the gateway and goes through the tunnel; even a hard-coded 8.8.8.8 is intercepted. IPv6 is disabled outright.

04 / KILL SWITCH

If the proxy drops, does traffic fall back to my normal connection?

No tunnel, no network

When the proxy process crashes or the VPN disconnects, traffic is blocked rather than leaking out directly. mihomo is restarted automatically and gluetun reconnects on its own; the workspace keeps running.

05 / HOST NETWORK

I don't want to change my whole machine's network setup.

Your host network stays as is

Every firewall rule lives in the container's own network namespace. Your browser, system proxy and other apps keep using the network they always did.

06 / WEIGHT

Do I need a full virtual machine for this kind of isolation?

Two containers, a real terminal

No extra VM. You get bash, tmux, git, node, python and a build toolchain — not a toy sandbox. tmux sessions persist, so tasks keep running after you close the terminal or drop SSH.

HOW IT WORKS

One path out,
every other path denied.

The gateway container owns the network stack. The workspace container has no network interface of its own; it shares the gateway's network namespace and can only leave through it. All network-admin privileges live in the gateway — the container the AI runs in has none.

  • Going direct: anything in the gateway that tries to leave via eth0 without the tunnel is rejected by the firewall.
  • Host or LAN proxies: the gateway's upstream connections may only reach public addresses, so the Clash on your machine is out of reach.
  • Docker's built-in DNS: 127.0.0.11 may forward through the host, so it's blocked; DNS only goes through the gateway.
  • IPv6: disabled via sysctl and dropped by ip6tables; if neither takes effect, the gateway refuses to start.
  • mihomo gateway (Clash Meta core): uses a subscription or Clash nodes. TUN takes over all traffic at layer 3, so programs that ignore proxy env vars can't slip out.
  • gluetun gateway: your own WireGuard, or a commercial VPN supported by gluetun (WireGuard / OpenVPN), with its built-in kill switch.
  • Firewall first, proxy second: it's default-deny from the moment it boots. The proxy's control API stays inside the gateway, so the agent can't switch it to direct mode.
  • Scope: image pulls and docker build use the host network and are outside the runtime isolation. The AI tools themselves are installed at runtime, through the tunnel.

STRICT EGRESS

Your local Clash
can't be the upstream.

Local proxy apps have their own routing rules, and some traffic may go direct by design. If aibox used one as its upstream, it would no longer control where traffic exits. So the upstream must be a remote node or a subscription — paste the subscription URL you already use in Clash.

  • Layer one, config validation: node addresses can't be localhost, *.internal, *.local, or private/reserved ranges, and type: direct is rejected.
  • Layer two, the firewall: even if a domain in your subscription resolves to the host or LAN, the gateway can't connect to it.
  • Failures leave no trace: a rejected config returns non-zero and your previous config stays as it was.
  • Trade-off: nodes running on your LAN or Tailscale (100.64/10) are rejected too. There's no exception switch for now.

COMPARISON

A local proxy app
solves a different problem.

Local proxy apps are built for everyday browsing on the whole machine, and flexible routing rules are their strength. aibox does one thing: give an AI agent a workspace with a fixed exit and limited file access. You can use both at once — aibox doesn't touch your machine's proxy settings.

Files visible Unrelated to networking; the agent runs as your user and can read whatever you can. Only granted folders, each optionally read-only.

Best for Everyday networking on the whole machine. Letting an AI agent work for long stretches in isolation.

GET STARTED

Three steps.
The wizard does the rest.

You'll need Docker, plus a proxy subscription, Clash nodes or a WireGuard config. The first start builds images and installs the AI tools, which takes about 3–5 minutes. The CLI and wizard currently speak Chinese.

  1. [1]

    Install Docker

    On macOS use OrbStack or Docker Desktop and start it. On Linux use Docker Engine, then log out and back in once.

    macOS 
    brew install orbstack
    Linux 
    curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER

    Windows: install Docker Desktop with WSL2 integration enabled, then do everything below inside a WSL terminal.

  2. [2]

    Get aibox and run the wizard

    It asks about egress, granted folders and AI tools; press Enter to accept defaults. At the end it can install the aibox / ai commands with Tab completion, start everything and run the checks.

    bash
    git clone https://github.com/OWNER/aibox ~/aibox
cd ~/aibox
./aibox init
  3. [3]

    Start Claude Code in your project

    Log in once on first run; credentials persist in the home volume. Press Ctrl+b then d to detach while the task keeps going; run the same command to come back.

    ai c myapp
  • [1/5]Environment: Docker and Compose versions, plus the TUN device on Linux.
  • [2/5]Egress: subscription, nodes, WireGuard or a commercial VPN. Required.
  • [3/5]Folders: paths with Tab completion, each set to rw or ro.
  • [4/5]AI tools: which tools, port mappings, API keys (skip if you log in with an account).
  • [5/5]Other: time zone, mirror for faster builds; SELinux only if detected.
  • ai c myappStart Claude Code in /workspace/myapp
  • ai x myappStart Codex in the project
  • ai sOpen a plain shell (tmux)
  • ai lsList sessions
  • ai stStatus and exit IP
  • ai qStop (data is kept)

FOR AI AGENTS

Let the agent on your host
set it up for you.

Every setting has a non-interactive command. The repo's AGENTS.md and CLAUDE.md are read automatically by Codex and Claude Code; they spell out the setup flow, how to handle errors, and the safety boundaries not to cross. Open the repo and ask your agent to set up aibox.

Non-interactive setup · use your own URL and folders
./aibox init --defaults                     # default config; never overwrites
./aibox config proxy --sub "https://example.com/your-sub" --filter 'JP'
./aibox mounts add rw ~/code/myapp
./aibox mounts add ro ~/Documents/specs
./aibox config tools claude codex
# optional: only if you use an API key instead of logging in
printf %s "$ANTHROPIC_API_KEY" | ./aibox config key ANTHROPIC_API_KEY
./aibox config check && ./aibox up && ./aibox doctor --full
  • No prompts, just exit codes: 0 on success, non-zero on failure with the reason on stderr.
  • Failures don't touch your config: an invalid node, for example, rolls the write back, so retrying is safe.
  • Secrets stay off the command line: API keys come from stdin and VPN keys from environment variables, never command arguments.
  • No guessing, no overreach: the agent asks you for the subscription URL and folders, and won't edit firewall rules, widen mounts or mount the Docker socket.

DOCTOR

Is the isolation working?
Run one command and see.

aibox doctor --full doesn't just read config — it sends real requests from inside the container to check egress, DNS, IPv6, privileges and mounts, then simulates a disconnect, confirms traffic is blocked, and confirms recovery. Any failure means a non-zero exit.

  • EgressThe container's exit IP and region, compared with the host's; a warning if they match.
  • DNSResolution happens at the gateway; hard-coded 8.8.8.8 is intercepted; authoritative DNS sees the exit network, not your ISP.
  • IPv6IPv6 can't get out, and the container has no global IPv6 address.
  • IsolationWorkspace capabilities; direct egress is rejected; upstream limited to public addresses; control API unreachable.
  • KillStops the proxy or downs the VPN interface, confirms requests fail, then confirms automatic recovery.
  • MountsEach granted folder's actual permissions match the configured ro / rw.
aibox doctor --full

NOTEThe list above uses the mihomo gateway. With gluetun there are fewer DNS and isolation checks, and the disconnect test downs the VPN interface instead.

FAQ

Before you start,
a few questions.

Can I use the Clash already running on my computer?

No, by design. Clash's routing rules may send some traffic direct, and then the exit is no longer under control. Upstreams pointing at this machine, the host or the LAN are rejected by both config validation and the firewall.

Instead, paste the subscription URL you use in Clash: aibox config proxy --sub "URL".

Which systems are supported?

macOS (Apple Silicon and Intel; OrbStack recommended, Docker Desktop and Colima work too) and Linux (Docker Engine 25+ and Compose 2.24+).

Tested on Ubuntu 24.04 arm64 with Docker 29 and Compose 2.40; both gateways pass doctor --full, and the script is compatible with the bash 3.2 that ships with macOS. It hasn't yet been tested on a physical Mac, on SELinux systems (Fedora / RHEL) or with rootless Docker — reports are welcome.

How long does the first start take?

About 3–5 minutes: two images are built, then the AI tools you chose are installed through the tunnel. Later starts don't rebuild; tools, logins and shell history live in a persistent home volume.

How do I use it on Windows?

Inside WSL2: install Docker Desktop with WSL2 integration, then git clone and run ./aibox init in a WSL terminal. From there it works the same as on Linux.

Is --yolo safe?

ai c myapp --yolo skips the tool's own per-action confirmations. The container is the sandbox: the agent can only change folders you granted as rw, and the network only goes through the gateway. Inside rw folders it can change anything, so grant reference material as ro and keep projects under git.

What happens when the proxy node goes down?

Programs in the container simply can't connect; nothing falls back to your local network. It reconnects automatically when the node is back, with no container restart. If aibox up reports an unhealthy gateway, check aibox logs gateway — usually the subscription failed to download or no node is reachable.

Is aibox affiliated with Anthropic or OpenAI?

No. aibox is an independent open-source project that runs these tools in a container. It is not affiliated with or endorsed by Anthropic or OpenAI. Using Claude Code or Codex is subject to their respective terms.
